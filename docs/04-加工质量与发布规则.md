# 离线加工、质量与发布规则

当前版：2.0-offline，2026-11-03。机器规则见 `config/model/policies.json`，字段映射见 `config/model/source-field-mapping.json`。已发布历史数据保留原规则版本，不修改旧验证记录冒充新构建。

## 采集与重跑

按来源月份完整下载并校验SHA-256，Citi Bike ZIP逐成员处理并检查CRC。ODS稳定身份由来源对象、成员与逻辑记录序号决定；同内容但原始位置不同的出租车记录保留，不能只按内容摘要删除。

ODS按完整来源分区校验后用Delta replaceWhere原子替换；已完整接收的相同来源对象可复用。DWD按目标开始日期窗口重建，骑行先检查ride_id内容冲突再去重。源文件修订后不能只追加新值而留下旧分区残留。

当前来源周期是月度，DWD和指标首版只验证了2025年6月。日期补跑和多月扩展必须显式传入业务范围，并验证相邻月、时区和分区覆盖，不能把脚本目录的存在当成已实现任意日期加工。

## 清洗与质量

- 保存原始时间文本、纽约当地时间和UTC瞬时值；夏令时歧义、不存在及解析失败需隔离。
- 核心时长域：出租车大于0且不超过24小时，骑行大于0且不超过72小时；不因运行失败放宽规则。
- 出租车距离在合格值域内才参与均值，费用异常可带警告保留。空间未匹配保留行程但排除对应区域/OD指标。
- 检查全部逻辑键、非空、事实外键和输入去向；输入等于有效、不同原记录隔离、重复跳过和范围外之和。
- 日天气检查日期完整性和核心质量标志，缺失不补晴天。指标总量和空间子集与已验证DWD核对。
- 未获得五月边界前，完整到达量与净流入被阻断发布，保持NULL；OD仍是六月出发行程队列。

质量结果保存ops.quality_result，记录级问题保存ops.quarantine_record。阻断失败不发布；警告失败数量可以非零，passed表示已满足该规则门禁或隔离策略。

## 版本与发布

历史作业固定ODS/DWD及维度版本，构建清单记录规则、模式、代码摘要、来源校验和结果行数。DWS按目标月份覆盖，ADS按release_id隔离候选。ClickHouse逐表核对行数、逻辑键和全部完整记录摘要，验证后原子交换历史/质量指针；失败保留原可读版本。

相同输入与代码重跑应复用已验证发布；输入或模型规则改变时生成新候选，不直接修改旧结果或验收JSON。Spark计算共享互斥锁，阻止两个本地driver同时构建。调度器失败重试不得绕过门禁。

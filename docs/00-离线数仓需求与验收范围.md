# 城市出行数仓系统的设计与实现：离线版需求与验收范围

版本：2.0-offline；范围调整日期：2026-11-03。用户已明确选择离线数仓，并取消实时站点功能。本说明是当前实施和验收范围；原始需求文档和旧设计保留供追溯，涉及实时场景的旧条款不再作为本版交付要求。

## 目标与数据

以纽约官方公开数据完成历史出行分析：Yellow Taxi行程、Citi Bike骑行、NOAA日天气、官方区域编码与边界。首版覆盖2025年6月，后续按需要扩展。禁止虚构业务记录。下载时使用网络，已下载数据可在本机按批次加工；“离线”指批量处理方式，浏览器和BI查询照常使用。

保留七个维度和两张历史行程事实表，按照ODS、DWD、DWS、ADS四层组织数据。历史骑行的起终站点继续作为维度，用于行程分析。取消当前车辆/空桩、实时缺车/满桩、GBFS持续采集、Kafka流式链路和相应实时性能目标。

## 功能要求

1. 按来源月份采集真实历史文件，保留来源URL、SHA-256、对象身份及行数。失败可重试，成功批次可复用。
2. DWD完成类型、纽约时区、去重、有效性、空间匹配和维度关联；质量异常可追溯到ODS原记录，不直接丢失源数据。
3. DWS统一生成行程日/小时、区域小时、OD及天气主题汇总；ADS供业务看板查询，发布前检查逻辑键、计数和完整内容。
4. 使用Airflow调度从采集、ODS验收到DWD、DWS、ADS、看板检查和导出的完整离线链路，保留任务依赖、失败重试与日志；当前只开放已验收的2025年6月参数。
5. 提供历史总览、区域与OD、天气对比、数据质量四个看板及CSV导出，指标与时间范围清晰。补充课程要求的地图和筛选交互验收。
6. 支持关键层重跑、来源与版本追溯；测试含批次复用、数据完整性、图表查询和重启后的入口可用性。

## 指标与边界

核心包括行程量、小时高峰、平均时长、出租车平均距离、区域出发量、六月出发行程OD、按降水组和周类型比较的日均需求，以及质量隔离率/覆盖率。

当前有效行程9,012,795条，仅代表已接入Yellow Taxi和Citi Bike两类记录。骑行源不含真实行驶距离，不编造该指标。未采集五月边界前，完整事件到达量与净流入保持不可用。日天气不能推断小时天气；比较不表示因果；未接入节假日日历时不声称已完成节假日分析。

## 验收与交付

验收至少包含一个完整月真实数据、四层链路、七维度两事实、来源和质量记录、离线指标、四个看板、地图与筛选、批次重跑、调度与运行日志、失败阻断和服务重启检查。

交付代码、SQL、数据字典、模型图、部署操作说明、测试记录、报告、PPT和操作录屏。无需Kafka、GBFS接口或实时看板。推荐技术栈为Docker Compose、Python、Spark、Delta Lake、ClickHouse、Airflow与Superset。

# 离线数仓参考案例学习与项目映射

参考：[大数据篇：数据仓库案例](https://www.cnblogs.com/ttzzyy/p/13255841.html)。2026-11-03学习并按用户选择调整为离线项目。网页与来源记录保存在 `work/references/cnblogs-13255841`。

文章是电商离线数仓教程：日志与MySQL业务数据进入HDFS/Hive，DolphinScheduler编排，ODS留原始数据，DWD清洗建模，DWS日汇总，DWT主题宽表，ADS面向报表。它还展示全量、增量、新增及变化同步、低变化维表、用户拉链表，以及按业务日期分区重跑。

| 参考方法 | 城市出行项目采用方式 |
| --- | --- |
| 分类同步策略 | 月度官方行程文件完整入仓，天气与区域有来源版本，已接收对象复用 |
| 分层职责明确 | ODS原始记录 → DWD两类行程与七维度 → DWS公共汇总 → ADS看板数据 |
| DWT主题复用 | 先用当前DWS/ADS满足需求，复用价值明确后再决定是否增加主题层 |
| 分区覆盖与重跑 | 先校验候选，再Delta replaceWhere或新版本发布，避免重复累加 |
| 维度历史管理 | 历史站点按来源月份快照，不宣称有完整SCD2变更来源 |
| 日批依赖编排 | 使用Airflow串联采集到ADS的十步依赖，固定允许的业务月份参数并保留失败重试 |
| ADS报表服务 | ClickHouse完成多维查询，Superset展示历史分析与质量结果 |

业务转换为出租车、骑行、区域和天气，不复制商城订单/优惠券或模拟用户日志。保留已部署Python、Spark、Delta、Airflow、ClickHouse、Superset；没有必要为外观相似再部署一套Sqoop、Flume或旧版集群。

当前交付已包含离线全链路编排、地图/筛选验收、失败阻断和短时稳定性检查；重启与重复运行记录在outputs验收报告中。用户已取消实时站点，旧实现仅归档，不再把Kafka/流处理或实时延迟列为当前交付任务。

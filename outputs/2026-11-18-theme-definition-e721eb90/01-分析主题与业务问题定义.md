## 1. 项目定位与使用角色

本项目以城市历史出行为总主题，以2025年6月纽约Yellow Taxi和Citi Bike的有效行程为分析对象，结合区域信息与中央公园日天气，围绕出行需求与时间规律、区域出发与OD联系、天气与出行量对比三个分析主题组织业务问题、指标和图表。系统为历史运营复盘和城市出行分析提供可追溯的数据依据，结论限定于已接入的数据、统计期间及空间覆盖范围。

预期使用角色包括城市交通分析人员、出行运营分析人员及课程评审人员。这是本项目拟服务的使用场景，不表示已有真实单位部署或访谈记录。主要使用方式是按日期、交通方式和空间范围查看历史分布，并沿指标追溯到统计口径与来源。

本项目将“城市历史出行”作为总主题，在其下组织三个分析主题；出租车行程与共享单车骑行是业务过程。分析主题围绕要回答的问题组织，可以跨两个业务过程，也可以复用同一事实表；不要求一个分析主题对应一张事实表或一张独立看板。数据质量作为三个主题的共同保障，不与业务主题混为一谈。

## 2. 数据范围与共同约定

- 统计范围：2025年6月纽约当地开始日期；交通方式限Yellow Taxi与Citi Bike。行程量用于描述已接入的出行活动，不等于全市总出行量，也不包含未实现的出行需求。
- 来源：官方历史行程文件、NOAA中央公园日天气、官方出租车区域编码及边界；当前为程序化下载与批量入仓，网页爬取增强在待办第9项另行实施。
- 时间：保留UTC作为小时唯一标识，展示转换为America/New_York；只定义已验收月份，不据此声称支持任意月份或全年分析。
- 周类型：只区分周一至周五与周六/周日；不将前者等同于排除法定节假日后的工作日。
- 空间：时间总量可包含空间未匹配的有效行程；区域出发只计起点匹配，OD只计两端匹配。对比必须解释子集差异，保留同区OD。
- 天气：同月、同方式、同周类型内比较；未记录可测降水不必然是晴天。微量降水单列，缺失不补晴天；结果仅为观察性关联。
- 发布与筛选：实际分析优先读取已验证的ads.bi_*视图；跨表使用同一已验证发布快照。日期与方式筛选范围保持一致。
- 空值与零值：只有来源完整且确无行程时才记0；未知、缺失、无基准、零分母保持不可用。平均值和比率从分子分母重新计算。
- 当前不纳入：完整事件到达量、净流入、实时站点库存、供需缺口、拥堵成因、因果效应、预测、全年趋势、节假日效应。

### T01 出行需求与时间规律

识别已接入两类行程在日期、小时和周类型上的分布及差异，为历史需求复盘、关注时段选择提供依据。

业务价值：确定值得进一步调查的日期和时段，比较两类出行的时间特征。

解读边界：行程量是已接入记录所反映的出行活动，不含未满足需求；不据高峰推断通勤目的，不把行程量变化直接解释为效率变化。

### T02 区域出发与OD联系

识别区域出发热点、热门起终点组合和不同方式的空间特征，并评估空间匹配覆盖范围。

业务价值：确定需要重点关注的区域和区域联系，为区域运营复盘提供线索。

解读边界：分析的是六月开始的行程；OD可包含六月出发、七月结束的记录，不等于按到达时刻统计的六月到达量；出发热点不能直接解释为运力缺口。

### T03 天气与出行量对比

在同月、同交通方式、同周类型内比较不同降水组的日均行程量，识别值得进一步验证的天气关联。

业务价值：为不同天气背景下的历史运营复盘和后续研究提供依据。

解读边界：仅使用中央公园单站日级天气；不代表全市每个地点或每个小时的天气，不推断因果，不进行需求预测。

## 5. 十二个业务问题的执行约定

### T01-Q01 2025年6月两类出行的每日行程量如何变化，哪些日期值得进一步关注？

- 业务用途：识别需要结合其他信息进一步核查的高低值日期。
- 指标与计算约定：有效行程量、各方式日行程量、两类接入行程合计。按日期、方式汇总trip_count；合计只相加已接入的两类记录。异常高低先作描述，不直接解释成事件影响。
- 分析维度与粒度：当地开始日期×交通方式。
- 图表与结果形式：双方式日趋势折线图＋总量卡片。
- 数据映射：dws.trip_day → ads.trip_day（查询ads.bi_trip_day）。
- 当前支撑：已有图表支持。历史总览：有效行程量、日趋势。
- 后续分析工作：补充具体高低值日期、对比数值和可追溯说明。
- 核对要求：两类日汇总可分别对上各自行程总量；日期范围及来源完整性可见。
- 解读边界：一月数据不支持年度季节性或同比；高低值本身不证明原因。

### T01-Q02 两类出行的小时分布和峰值时段有什么差异？

- 业务用途：确定历史出行活动较集中的小时，帮助选择重点复盘时段。
- 指标与计算约定：当地小时日均出发量、观测峰值小时。选定日期内该小时trip_count总和÷来源完整的选定日期数；必须包含完整且零出行的日期，不能只数非零日期。
- 分析维度与粒度：当地小时×交通方式；按开始日期筛选。
- 图表与结果形式：24小时双方式日均曲线或分组柱图。
- 数据映射：dws.trip_hour → ads.trip_hour（查询ads.bi_trip_hour）。
- 当前支撑：已有图表支持。历史总览：纽约当地小时·日均出发量。
- 后续分析工作：根据数据指出观测峰值，解释与配置高峰标签的区别。
- 核对要求：完整六月分母为30；缩小日期范围后分母同步变化；UTC小时转换为America/New_York。
- 解读边界：dim_time中的预设早晚高峰标签不能代替观测结果；不判断通勤目的。

### T01-Q03 周一至周五与周末的日均行程量、日内分布有什么不同？

- 业务用途：比较不同周类型的历史活动强度和时段差异。
- 指标与计算约定：分周类型日均行程量、分周类型小时日均出发量。同方式同周类型行程总量÷该周类型完整日期数；小时图再按当地小时分组。两组分别计算分母。
- 分析维度与粒度：周一至周五/周末×交通方式；小时为下钻。
- 图表与结果形式：周类型日均柱图＋分面24小时曲线。
- 数据映射：dws.trip_day / dws.trip_hour 关联 dwd.dim_date；现有日期/小时数据可派生。
- 当前支撑：数据已支持，需补分析图。现有日/小时汇总；历史总览尚无独立的完整周类型对比图。
- 后续分析工作：后续第8项补分组计算、图表和结论。
- 核对要求：两组各自显示完整样本天数；分组总量可回加到选定日期总量。
- 解读边界：is_weekday只表示周一至周五，不是剔除法定假日后的工作日。

### T01-Q04 两类行程平均时长如何变化，出租车平均距离能补充说明什么？

- 业务用途：描述已发生行程的时间和出租车距离特征，辅助解释需求结构。
- 指标与计算约定：平均行程时长（分钟）、出租车平均距离（公里）、各指标有效记录数。SUM(duration_sum_seconds)÷SUM(duration_count)÷60；出租车距离为SUM(distance_sum_km)÷SUM(distance_count)；零分母返回NULL。
- 分析维度与粒度：开始日期或当地小时×交通方式；距离只看出租车。
- 图表与结果形式：时长对比表/趋势图＋出租车平均距离摘要。
- 数据映射：dws.trip_day / dws.trip_hour → ads.trip_day / ads.trip_hour。
- 当前支撑：已有图表支持。历史总览：平均时长、出租车平均距离。
- 后续分析工作：后续分析附上有效分母，必要时补日期或小时趋势展示。
- 核对要求：跨日跨小时重新汇总分子分母；骑行真实距离保持不可用。
- 解读边界：不平均每日平均值；不将时长增长直接归因为拥堵或效率下降。

### T01-Q05 消除两类记录总量差异后，它们的日内出发分布是否仍有差异？

- 业务用途：用可比尺度查看两种方式在一天内的相对活跃时段。
- 指标与计算约定：各方式内部的小时出发占比。同方式、同日期范围内某当地小时行程量÷该方式在相同日期范围内的全部行程量；零分母返回NULL。
- 分析维度与粒度：当地小时×交通方式；周类型可分面。
- 图表与结果形式：两条方式内归一化小时分布曲线。
- 数据映射：dws.trip_hour / ads.trip_hour按方式汇总派生。
- 当前支撑：数据已支持，需补分析图。现有小时汇总支持；该归一化图尚未单独实现。
- 后续分析工作：后续第8项补方式内占比计算和对比图。
- 核对要求：每个有记录方式的24小时占比合计约100%；两方式使用相同日期范围。
- 解读边界：这是方式内部时间分布，不是纽约市交通方式分担率，不证明两方式互相替代。

### T02-Q01 哪些行政区、区域的出发量较高，两类出行的热点是否不同？

- 业务用途：确定值得进一步关注的出发热点和方式差异。
- 指标与计算约定：区域出发量、行政区出发量、区域排名。按区域或行政区、方式汇总departure_count；仅统计起点成功匹配的有效行程；先筛选再排名。
- 分析维度与粒度：日期范围×交通方式×行政区×起点区域。
- 图表与结果形式：出发量分级地图＋区域Top15＋行政区分组柱图。
- 数据映射：dws.zone_hour → ads.zone_hour（查询ads.bi_zone_hour）。
- 当前支撑：已有图表支持。区域与OD看板；地图与日期/方式/行政区/区域筛选。
- 后续分析工作：补充各方式热点对比结论，并标明空间覆盖率。
- 核对要求：区域总量对齐起点匹配行程数；筛选范围和单位清晰。
- 解读边界：绝对量热点不等于单位面积密度、人口出行率或运力缺口。

### T02-Q02 热门起终点组合有哪些，Top20占全部有效OD记录的多少？

- 业务用途：描述已接入行程中较集中的区域联系。
- 指标与计算约定：OD行程量、OD排名、Top20集中度。按方式、起区、终区汇总trip_count；集中度=同一日期/方式筛选范围内Top20的OD量÷该范围内全部双端匹配OD量。
- 分析维度与粒度：日期范围×交通方式×起点区域×终点区域。
- 图表与结果形式：OD Top20排行或矩阵＋Top20集中度摘要。
- 数据映射：dws.od_day → ads.od_day（查询ads.bi_od_day）。
- 当前支撑：已有排行，需补集中度指标。区域与OD：热门OD前20；现有导出仅Top20，不能充当全量分母。
- 后续分析工作：后续第8项从完整OD数据计算分母，补集中度。
- 核对要求：保留A→B与B→A方向；先筛选再取Top20；同区OD保留并注明。
- 解读边界：只包含六月开始且两端匹配的行程；不等同完整到达量或净流入。

### T02-Q03 选定热点区域的小时出发规律，与总体规律有什么差异？

- 业务用途：为区域运营复盘选择重点时段。
- 指标与计算约定：选定区域当地小时日均出发量；可选方式内归一化曲线。选定区域、方式、日期范围内某当地小时departure_count总和÷该范围内完整日期数；总体参照使用相同空间匹配子集与时间范围。
- 分析维度与粒度：起点区域×当地小时×交通方式；日期筛选。
- 图表与结果形式：区域小时日均曲线＋相同口径的总体参照。
- 数据映射：dws.zone_hour / ads.zone_hour；现有日期地图不等于已提供小时图。
- 当前支撑：数据已支持，需补分析图。区域小时汇总已存在；选定区域小时分析图待补。
- 后续分析工作：后续第8项补区域小时图；两种曲线量级不同时分面或使用同类占比。
- 核对要求：统一当地小时和完整日期分母；总体参照只计起点匹配行程。
- 解读边界：本问题只分析出发活动，不分析到达、库存、缺车或区域供需缺口。

### T02-Q04 有多少有效行程可以参与区域分析和OD分析，覆盖率差异会怎样限制解读？

- 业务用途：让热点与OD结论附带可核查的覆盖范围。
- 指标与计算约定：起点匹配率、终点匹配率、双端匹配率。起点匹配率=SUM(origin_mapped_count)÷SUM(trip_count)；终点匹配率=SUM(destination_mapped_count)÷SUM(trip_count)；双端匹配率=SUM(od_mapped_count)÷SUM(trip_count)；零分母返回NULL。
- 分析维度与粒度：开始日期范围×交通方式。
- 图表与结果形式：三类覆盖率对比表＋空间分析说明。
- 数据映射：dws.trip_day → ads.trip_day；起点/终点/双端覆盖率由现有分子派生。
- 当前支撑：已有图表支持。区域与OD：空间匹配率；与数据质量看板联查。
- 后续分析工作：将覆盖率作为各空间结论的配套说明。
- 核对要求：分母包含全部有效行程；不受行政区/单区域筛选影响；OD总量对齐双端匹配数。
- 解读边界：未匹配行程保留在总量中；匹配率不表示空间定位精度或无抽样偏差。

### T03-Q01 同一周类型下，不同降水组的日均行程量有什么差异？

- 业务用途：比较不同天气背景下的历史活动强度，避免样本天数不同导致总量误判。
- 指标与计算约定：降水组日均行程量、完整样本天数。同月、同方式、同周类型、同降水组trip_count÷complete_days；降水分未记录可测降水、微量降水、可测降水。
- 分析维度与粒度：月份×交通方式×周一至周五/周末×降水组。
- 图表与结果形式：分周类型降水组日均柱图＋样本天数。
- 数据映射：dws.weather_group → ads.weather_group（查询ads.bi_weather_group）。
- 当前支撑：已有图表支持。天气对比：周一至周五/周末的降水组日均量。
- 后续分析工作：补充比较数值、样本量与观察性结论。
- 核对要求：同组内比较；微量降水单列；缺失天气不填无降水；样本天数可见。
- 解读边界：天气以中央公园单站日观测为背景；不解释为全市逐时天气影响。

### T03-Q02 相对各自无可测降水基准，两类出行的变化幅度有什么差异？

- 业务用途：在各方式自有基准上比较相对变化，降低原始规模差异的干扰。
- 指标与计算约定：天气需求比率、相对基准变化百分比。比率=目标组日均量÷同月同方式同周类型no_measurable组日均量；相对变化=(比率−1)×100%；无基准、无样本或零分母返回NULL。
- 分析维度与粒度：月份×交通方式×周类型×降水组。
- 图表与结果形式：基准为1的比率图或表＋样本天数。
- 数据映射：ads.weather_group现有demand_ratio；相对百分比为展示派生。
- 当前支撑：已有图表支持。天气对比：天气对比样本与需求比率表。
- 后续分析工作：后续解释每种方式对应的独立基准；可补百分比展示。
- 核对要求：不跨周类型共用基准，不对多个方式/周类型的比率直接平均。
- 解读边界：相对变化仅描述关联，不是天气弹性、因果效应或预测结果。

### T03-Q03 各天气对比使用了多少天，哪些比较应因样本有限而谨慎解释？

- 业务用途：帮助读者判断天气结论的证据范围和后续采集需要。
- 指标与计算约定：各方式、周类型、降水组完整样本天数；基准样本天数。按分组展示complete_days，基准天数从同组no_measurable记录关联；某组没有记录表示无样本，不补成零行程。
- 分析维度与粒度：月份×交通方式×周类型×降水组。
- 图表与结果形式：天气样本与比率明细表；结论旁附样本说明。
- 数据映射：dws.weather_group / ads.weather_group完整分组记录。
- 当前支撑：已有图表支持。天气对比：样本与需求比率表。
- 后续分析工作：补基准组天数引用及结论适用范围说明。
- 核对要求：每个方式各天气组完整天数合计可对上完整月份；不将两方式天数相加当独立天气样本数。
- 解读边界：不预设统计显著性；小样本提示不等于完成假设检验。

## 6. 图表与筛选使用约定

1. 时间主题按当地开始日期和交通方式比较；跨方式比较使用相同日期范围。完整六月小时日均分母为30，筛选后按对应完整日期数重新计算。
2. 空间主题先区分全部有效行程、起点匹配行程和双端匹配行程，再比较总量或排名。行政区筛选只用于对应区域出发数据，当前Superset中不自动作用于OD排行与全局覆盖率。若以后对OD增加空间筛选，必须明确作用于起点、终点还是两端。
3. 天气主题沿用当前完整六月天气分组和交通方式筛选；周类型作为明确分组。当前weather_group没有按日明细，不宣称天气看板支持任意日期片段重算；若以后增加该能力，需要从日级数据重新聚合。
4. 质量看板使用来源、批次等质量维度；不能直接把行程日期或单区域筛选套在批次质量率上。
5. 每张用于结论的图必须附日期范围、来源/交通方式、单位、必要的分母或样本天数，并保留发布版本或导出时间便于复查。
